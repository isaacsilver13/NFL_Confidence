### Blocker #3: Align Backend and Frontend on Pick Locking
**Impact:** Confusing UX; users can't submit valid picks  
**Timeline:** 45 minutes  
**Requirement:** Backend behaves like frontend - ALL picks locked on first game kickoff

**Step 3.1: Clarify Locking Behavior**
- **Decision:** All picks lock when earliest game (first kickoff) occurs
- **Rationale:** Matches current frontend behavior; prevents "late" Thursday pick from being used for Sunday prediction
- **Consistency:** Week-level lock, not per-game (simplest model)
- **Consequence:** Users must submit complete card before first kickoff

**Step 3.2: Update Backend Validation**
- **File:** `backend/app/services/picks_service.py`, line 115+
- **Current:** Validates each game individually
  ```python
  for submission in submissions:
      game = game_by_id.get(submission.game_id)
      if game.kickoff_time <= now:  # Per-game check
          raise ValidationError(...)
  ```
- **New:** Validate against week's earliest game (first kickoff)
  ```python
  # Get the earliest game kickoff for the week
  earliest_kickoff = min((g.kickoff_time for g in games), default=None)
  if earliest_kickoff and earliest_kickoff <= now:
      raise ValidationError("Picks are locked. The earliest game has already started.")
  ```

**Step 3.3: Simplify Frontend Lock Calculation**
- **File:** `frontend/src/pages/PicksPage.tsx`, line 55-58
- **Current:** Already correct (week-level lock)
  ```typescript
  const isLocked = Boolean(week.isLocked || (locksAt !== null && locksAt <= now))
  ```
- **Status:** ✅ No change needed - frontend already implements week-level lock

**Step 3.4: Update Error Messages**
- **File:** `backend/app/services/picks_service.py`
- **Change:** Error message should reference week lock, not individual game

**Step 3.5: Update Database Tests**

**Impact:** Production outages under concurrent load  
**Timeline:** 15 minutes  

**Step 3.1: Update Database Engine Configuration**
- **File:** `backend/app/db/session.py`
- **Current:**
  ```python

  ```
- **New:**
  ```python
  engine = create_engine(
      settings.database_url,
      pool_size=10,           # Support 10 concurrent connections
      max_overflow=5,         # Allow up to 15 during spikes
      pool_pre_ping=True,     # Verify connection before reuse
      pool_recycle=3600,      # Refresh connections after 1 hour
  )
  ```

  ```python
  # Pool sizing rationale:
  ```

### Bug #4: Improve Scheduled Job Logging
**Impact:** Operational difficulty; silent failures  
**Timeline:** 20 minutes  

**Step 4.1: Add Contextual Logging**
- **File:** `backend/app/jobs/scheduler.py`
- **Current:**
  ```python
  def _run_logged(job_name: str, job) -> None:
      try:
          job()
      except Exception:
          logger.exception("Scheduled job failed job=%s", job_name)
  ```
- **New:**
  ```python
  import logging
  import time
  
  logger = logging.getLogger(__name__)
  
  def _run_logged(job_name: str, job, **context) -> None:
      """Run a scheduled job with comprehensive logging and timing."""
      start = time.time()
      logger.info(f"Job starting", extra={"job_name": job_name, **context})
      try:
          result = job()
          elapsed = time.time() - start
          logger.info(
              f"Job completed",
              extra={"job_name": job_name, "elapsed_seconds": elapsed, "result": result, **context}
          )
      except Exception as e:
          elapsed = time.time() - start
          logger.exception(
              f"Job failed",
              extra={"job_name": job_name, "elapsed_seconds": elapsed, **context},
              exc_info=e
          )
          # Optional: Increment failure metric, send alert
  ```

**Step 4.2: Update Job Invocations**
