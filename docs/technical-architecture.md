# Backend Architecture

Routes should never contain business logic.

Routes:

Receive requests.

↓

Validate input.

↓

Call service.

↓

Return response.

Business rules belong inside Services.

Database access belongs inside Repositories.

---

Example

Route

POST /api/picks

↓

PickService.submit_picks()

↓

PickRepository.save()

↓

Database

---

# Repository Pattern

Repositories are responsible only for:

- Reading database records
- Writing database records
- Transactions

Repositories must never contain business rules.

---

# Service Pattern

Services are responsible for:

- Validation
- League rules
- Confidence validation
- Scoring
- Locking picks
- Notifications

Every feature should have a corresponding service.

Example

LeagueService

PickService

ScoreService

ReminderService

GameService

LeaderboardService

# Error Handling

Never expose stack traces.

Always return structured errors.

All backend exceptions must be logged.

Unexpected exceptions return HTTP 500.

Validation errors return HTTP 400.

Authentication failures return HTTP 401.

Authorization failures return HTTP 403.

Not found returns HTTP 404.

# Guiding Principles

When making implementation decisions:

1. Simplicity beats cleverness.

2. Explicit beats implicit.

3. Readability beats brevity.

4. Mobile experience comes first.

5. Reliability is more important than new features.

6. Business rules belong in services.

7. UI components should be reusable.

8. Database schema should be normalized.

9. APIs should remain backwards compatible whenever possible.

10. If multiple implementations are possible, choose the one that is easiest for future developers to understand.
